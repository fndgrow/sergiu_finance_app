# Casieria EHL — касса строительной фирмы

Мобильное веб‑приложение (PWA) для учёта денег небольшой строительной фирмы в Молдове. Ставится на телефон как обычное приложение, работает офлайн, данные общие для всех сотрудников и хранятся на собственном сервере фирмы. Логика расчётов повторяет Excel‑файл «Evidență casierie EHL», с которого всё началось, и расширяет его.

Адрес рабочего экземпляра: https://casa.fndgrow.md. Интерфейс на румынском и русском (кнопка языка вверху).

Этот файл — для тех, кто пользуется приложением и хочет понимать цифры. Техническое описание кода, базы, синхронизации и сервера — в [ARCHITECTURE.md](ARCHITECTURE.md) (на английском).

## 1. Роли и вход

Есть две роли.

| | Оператор (сотрудник) | Директор |
|---|---|---|
| Вход | числовой код 4–8 цифр | код + пароль |
| Видит | экран «Добавить», «Мои записи» (только свои), свой баланс | всё: панель, все журналы, настройки, пользователей |
| Может | создавать записи (кроме поступлений от клиентов и договоров), редактировать свои в течение 15 дней | создавать, редактировать любые, удалять, управлять пользователями и настройками |
| Не видит | оклады и историю окладов, чужие записи, сводку | — |

**Коды.** Каждому пользователю директор задаёт код в Setări → Utilizatori. Код вводится на телефоне один раз, дальше приложение открывается без вопросов. Восемь неверных кодов подряд с одного адреса блокируют вход на 15 минут.

**Пароль директора.** При самом первом входе директор задаёт пароль (не короче 8 символов). Дальше на каждом новом телефоне и затем раз в неделю приложение просит его снова; код при этом помнит. Это не только экран: сессия директора на сервере живёт ровно 7 дней. Сменить пароль: Setări → Parola directorului. Смена пароля завершает сессии директора на всех других телефонах.

**Первый запуск на пустой базе.** Самый первый введённый код становится кодом директора, затем приложение просит задать пароль. Поэтому после установки сервера приложение нужно открыть сразу самому.

**Отключение сотрудника.** Статус Inactiv в карточке пользователя. Его телефон теряет доступ при следующем запросе; данные, которые он вносил, остаются.

**Выход.** Кнопка «Schimbă utilizatorul» внизу экрана «Добавить» (оператор) или в настройках (директор).

## 2. Модель денег: три кассы, счёт, люди

Деньги фирмы лежат в четырёх местах, и приложение следит за каждым.

1. **Касса (Casa).** Наличные. Ведётся по «полкам», по одной на валюту: MDL, EUR, USD, RON и любые добавленные. Каждая полка считается в своей валюте, а общий итог кассы — в леях по курсу на сегодня из настроек.
2. **Счёт (Cont).** Деньги в банке, считаются в леях.
3. **У сотрудников (La colaboratori).** Наличные, выданные людям под отчёт: авансы минус их расходы. Это тоже деньги фирмы, пока человек за них не отчитался.
4. **Кассир.** Человек, который физически держит кассу. Деньги, переданные ему, из кассы не уходят.

**Деньги фирмы (Banii firmei) = Касса + Счёт + Остатки у сотрудников.**

Движение денег:

```
Поступление наличными ─────► КАССА (полка валюты поступления)
Поступление переводом ─────► СЧЁТ (в леях по курсу строки)

КАССА ─ Dat persoanei ─────► сотрудник (аванс в леях по курсу)  ─ его расходы наличными ─► ушло из фирмы
КАССА ─ Depus pe cont ─────► СЧЁТ
КАССА ─ Salarii / Chirii numerar / Împrumut / Alte / расходы кассира наличными ─► ушло из фирмы
СЧЁТ  ─ расходы переводом / аренда переводом ─► ушло из фирмы
```

## 3. Операции (формы) и их поля

Все записи вносятся через экран «Добавить» (Adaugă). Поля со звёздочкой обязательны.

### 3.1 Încasare / Поступление
Деньги, полученные от клиента.

| Поле | Назначение |
|---|---|
| Data* | дата получения |
| Client* | имя клиента; подставляется из уже введённых |
| Proiect | проект, к которому относится; оператор видит только свои активные проекты |
| Descriere | например «Tranșa 2» |
| Valuta* | валюта, из списка в настройках |
| Curs* | курс к лею на дату; для MDL всегда 1 и не редактируется; для остальных подставляется из настроек, можно поправить |
| Suma* | сумма в выбранной валюте |
| Mod* | Numerar (наличными → касса) или Transfer (переводом → счёт) |

Внизу формы сразу показан эквивалент в леях = Suma × Curs.

### 3.2 Cheltuială / Расход
Деньги, потраченные на нужды фирмы. Только в леях.

| Поле | Назначение |
|---|---|
| Data* | дата |
| Suma (MDL)* | сумма в леях |
| Pe ce s-au cheltuit banii* | **обязательное описание**, минимум 3 символа: что именно куплено или оплачено. Без него ни форма, ни сервер запись не примут |
| Categorie* | категория из списка в настройках; можно ввести новую |
| Client, Proiect | к чему относится расход |
| Plătit de* | кто платил; у оператора подставляется его имя |
| Mod* | Numerar или Transfer |
| Plătit din* | только при наличных: **Avansul de la firmă** (из аванса) или **Banii mei** (из своих денег, фирма должна вернуть) |

### 3.3 Ieșire din casă / Выдача из кассы
Всё, что физически покидает кассу.

| Поле | Назначение |
|---|---|
| Data*, Valuta*, Curs*, Suma* | как в поступлении; сумма снимается с полки этой валюты |
| Destinație* | см. ниже |
| Persoana | кому выдано |
| Luna | только для зарплаты: за какой месяц |
| Nota | примечание |

Назначения (Destinație):

| Назначение | Что происходит |
|---|---|
| Dat persoanei | снимается с кассы, становится авансом человека в леях (Suma × Curs). Исключение: кассир — для него выдача не считается выходом из кассы |
| Depus pe cont | снимается с кассы, прибавляется к счёту |
| Salarii | снимается с кассы, учитывается как выплаченная зарплата за месяц из поля Luna |
| Împrumut | снимается с кассы (используется автоматически формой займа) |
| Alte | снимается с кассы, нигде больше не учитывается |

### 3.4 Chirie / cazare / Аренда
| Поле | Назначение |
|---|---|
| Data început*, Data sfârșit | период |
| Locația* | адрес или название |
| Chiriașul | кто живёт |
| Valuta*, Curs* | валюта платежа |
| Chirie, Gaj, Comunale, Avarii | составляющие; пустое = 0 |
| Mod* | Numerar: снимается с полки этой валюты; Transfer: со счёта |

Итого = Chirie + Gaj + Comunale + Avarii, в леях по курсу строки.

### 3.5 Împrumut / Займ
Деньги, выданные в долг человеку.

| Поле | Назначение |
|---|---|
| Data*, Persoana*, Suma (MDL)* | кому и сколько |
| Termen | срок возврата; просрочка считается по нему |
| Status* | Neachitat / Achitat |
| Banii au ieșit din casă acum | галочка только при создании: автоматически создаёт «Ieșire din casă → Împrumut» на ту же сумму, чтобы касса не осталась завышенной |

### 3.6 Contract / Договор
| Поле | Назначение |
|---|---|
| Client* | имя должно совпадать с именем в поступлениях |
| Sumă contract* | полная сумма в леях |
| De încasat cash | часть, которая по договору платится наличными; остальное переводом |

### 3.7 Pontaj / Табель
| Поле | Назначение |
|---|---|
| Luna*, Angajat* | месяц и сотрудник из списка активных |
| Zile 1–15, Zile 16–sfârșit | отработанные дни в каждой половине месяца |

Форма показывает рабочие дни месяца и (директору) сумму к начислению.

### 3.8 Angajat / Сотрудник
Имя, дата начала, статус, оклад в месяц. При изменении оклада создаётся новая запись в истории окладов с датой; старые месяцы продолжают считаться по старому окладу.

### 3.9 Proiect / Проект
Название, клиент, ответственные (выбор из людей), бюджет в леях, даты, статус (Activ / Pauză / Finalizat), примечание.

### 3.10 Utilizator / Пользователь (только директор)
Имя, роль, код доступа (подставляется случайный, можно изменить), статус. Галочка «Îl trec și la angajați» сразу заводит сотрудника с окладом.

## 4. Правила расчётов, по формулам

Обозначения: `Σ` — сумма по всем записям с условием; `curs_azi(V)` — курс валюты V из настроек; `curs` — курс, записанный в строке.

**Полка валюты V (в валюте):**
```
intrat(V)  = Σ Încasări[Numerar, valuta=V].suma
ieșit(V)   = Σ Ieșiri[valuta=V, destinatie ∈ {Depus, Dat persoanei (кроме кассира), Salarii, Împrumut, Alte}].suma
           + Σ Chirii[Numerar, valuta=V].total
           + (только для MDL) Σ Cheltuieli[Numerar, platitDe = кассир].suma
rămas(V)   = intrat(V) − ieșit(V)
```
**Касса в леях:** `Casa = Σ_V rămas(V) × curs_azi(V)`. Полка может уйти в минус: это сигнал, что из валюты выдали больше, чем в ней поступило наличными.

**Счёт:**
```
Cont = Σ Încasări[Transfer].suma×curs + Σ Ieșiri[Depus pe cont].suma×curs
     − Σ Cheltuieli[Transfer].suma − Σ Chirii[Transfer].total×curs
```

**Сотрудник P (в леях):**
```
primit(P)   = Σ Ieșiri[Dat persoanei, persoana=P].suma×curs
cheltuit(P) = Σ Cheltuieli[Numerar, platitDe=P].suma
proprii(P)  = Σ Cheltuieli[Numerar, platitDe=P, sursa=Proprii].suma      (справочно)
sold(P)     = primit(P) − cheltuit(P)
```
`sold > 0`: у человека на руках деньги фирмы. `sold < 0`: фирма должна ему. Кассир в этот отчёт не входит.

**Деньги фирмы:** `Casa + Cont + Σ_P sold(P)`.

**Итоги для панели:** Încasări = Σ всех поступлений × curs; Cheltuieli = Σ всех расходов; и так далее по строкам «Sumar bani».

**Округление.** Все суммы считаются с округлением до копеек (2 знака).

**Имена.** Люди, клиенты, категории и проекты сравниваются по тексту без учёта регистра и пробелов по краям. «Ion Popescu» и «ion popescu» — один человек; «Popescu Ion» — другой. Везде подставляются уже введённые имена, чтобы не плодить варианты.

## 5. Панель директора: что означает каждая цифра

Панель открывается у директора по умолчанию. Сверху вниз:

**Выбор месяца.** Шесть последних месяцев и «Toate lunile». Влияет только на две карточки под ним. Всё остальное на панели — накопительно с первого дня.

**Карточка Cheltuieli (расходы за месяц).**
Сумма расходов за выбранный месяц, стрелка и процент к прошлому месяцу (красная вверх = больше), кольцевая диаграмма по категориям с иконкой и процентом у каждой доли (доли меньше 6 % без подписи, они есть в списке ниже), легенда, список категорий с суммой и долей. Если категорий больше семи, младшие складываются в «Alte categorii». Нажатие на категорию открывает журнал расходов, отфильтрованный по этой категории и месяцу. Цвет категории закреплён за ней (по порядку в настройках), не меняется от месяца к месяцу.

**Карточка Flux de numerar (поток денег).**
Поступления минус расходы за месяц, два бейджа «+поступления» и «−расходы», столбики за шесть месяцев (зелёный — поступления, оранжевый — расходы). Нажатие на месяц выбирает его.

**Плитки.** Banii firmei, În casă, Pe cont, Încasări, Cheltuieli — определения из раздела 4. «Pe cont» красным, если счёт ушёл в минус.

**Sumar bani.** Разбивка: поступило наличными и переводом, расходы наличными и переводом, выплачено зарплат, выдано авансов (без кассира), внесено на счёт, оплачено аренды, «Rest de justificat» (сумма остатков у сотрудников; жёлтым, если больше нуля), итог.

**Casa pe valute.** Каждая полка: значок валюты, остаток в валюте, эквивалент в леях по курсу на сегодня, общий итог кассы. Минус красным.

**Raport pe colaborator.** По каждому человеку: статус («Are în mână bani ai firmei» / «Firma îi datorează» / «Sold zero»), получил, потратил, из них из своих денег, остаток. Нажатие открывает расшифровку (раздел 7).

**Sold pe client.** Поступило от клиента минус расходы, отнесённые на клиента.

**Cheltuieli pe categorie.** Полоски по категориям за всё время.

**Proiecte active.** По проекту: клиент, ответственные, потрачено / бюджет с полоской (красная, если бюджет превышен), получено. Нажатие открывает карточку проекта. Ниже «Alte proiecte» — названия проектов, встречающиеся в записях, но не заведённые как проекты.

**Contracte.** Сумма договоров, получено, осталось, процент получения.

**Salarii.** Начислено по табелю, выплачено, остаток к выплате, последние месяцы.

**Împrumuturi.** Выдано, возвращено, к возврату (и сколько займов открыто), просроченных.

**Chirii.** Итого оплачено аренды.

## 6. Журналы, фильтры, история изменений

Вкладка «Registre» (директор): Încasări, Cheltuieli, Ieșiri, Proiecte, Chirii, Contracte, Împrumuturi, Salarii, Istoric. Каждая строка открывается на редактирование; внизу формы у директора есть «Șterge» (нужно нажать дважды). Фильтр из панели показан полоской сверху с кнопкой «Șterge filtrul».

**Salarii** объединяет сводку по месяцам, табели (с ценой дня) и список сотрудников с текущим окладом.

**Istoric (история изменений).** Выбираете месяц, видите каждое добавление, изменение и удаление: кто, когда, что, со значениями на тот момент. Удалённые записи тоже здесь со всеми полями. Историю нельзя ни изменить, ни удалить, даже директору. Здесь же кнопка выгрузки в Excel.

**Ale mele (оператор).** Последние 60 записей, которые внёс этот пользователь; каждую можно открыть и поправить.

## 7. Баланс сотрудника

Пример. Директор выдал Иону 1 000 лей (Ieșire → Dat persoanei). Ион купил цемент на 500 из аванса и краску на 1 200 из своих денег (расход с «Plătit din = Banii mei»). Баланс Иона: 1 000 − 500 − 1 200 = −700. На панели у Иона стоит «Firma îi datorează 700», и «din banii proprii 1 200». Директор нажимает на строку и видит обе покупки с описаниями и выдачу 1 000. Когда директор вернёт Иону 700 (ещё одна выдача «Dat persoanei»), баланс станет 0.

Личные покупки (молоко себе) в приложение не вносятся: приложение учитывает только деньги фирмы.

Сотрудник видит свой баланс на экране «Добавить» (карточка «Soldul meu») и ту же расшифровку, только свою.

## 8. Зарплаты и табель

- У сотрудника есть история окладов: «с такой‑то даты оклад такой‑то». Для месяца берётся оклад, действующий на конец этого месяца.
- Рабочих дней в любом месяце считается 24 (правило фирмы, как в исходной таблице).
- Цена дня = оклад ÷ 24.
- Начислено за первую половину = дни 1–15 × цена дня; за вторую = дни 16–конец × цена дня; за месяц = их сумма. Фирма платит раз в две недели, поэтому форма табеля и журнал «Salarii» показывают обе половины отдельно.
- Выплачено за месяц = выдачи из кассы с назначением Salarii и этим месяцем в поле Luna.
- Остаток к выплате = начислено − выплачено. Отрицательный остаток значит, что выплатили больше, чем начислено по табелю.

Операторы оклады не видят: в форме табеля им показаны только рабочие дни.

## 9. Договоры

Поступления сопоставляются с договором **по имени клиента**: наличные поступления клиента идут в счёт части «cash», переводы — в счёт части «transfer».

```
rămas            = sumă contract − încasat cash − încasat transfer
rămas cash       = de încasat cash − încasat cash
rămas transfer   = (sumă − de încasat cash) − încasat transfer
procent încasat  = încasat / sumă × 100
```
Если у одного клиента два договора, все его поступления засчитаются в каждый (ограничение, см. раздел 20).

## 10. Займы

Сводка: выдано, возвращено (статус Achitat), к возврату, число открытых, число просроченных (срок прошёл, статус Neachitat). По человеку: всего и не возвращено. Возврат денег в кассу займом не оформляется: когда человек вернул, поставьте Achitat, а приход денег проведите отдельно (например, как поступление), см. раздел 20.

## 11. Аренда и проживание

Платёж наличными снимается с полки своей валюты, переводом — со счёта. На панели и в Excel есть помесячная сводка.

## 12. Проекты

Проект задаёт клиента, ответственных и бюджет. Оператору в формах предлагаются только активные проекты, где он ответственный (если таких нет, все активные). Расходы с этим проектом суммируются против бюджета; поступления по проекту показываются рядом. Статус Finalizat убирает проект из выбора, но история остаётся.

## 13. Настройки

Только директор.

- **Utilizatori.** Список пользователей с кодами; добавление, роль, статус.
- **Valute și cursuri.** Курс на сегодня для каждой валюты и добавление новой. Используется для итога кассы и как подсказка в формах, но не меняет курс в уже введённых строках.
- **Casierul.** Имя кассира (раздел 2).
- **Parola directorului.** Смена пароля.
- **Categorii de cheltuieli.** По одной в строке; порядок определяет цвет на диаграмме.
- **Export Excel.** За всё время или за выбранный месяц.
- **Schimbă utilizatorul.** Выход.

## 14. Выгрузка в Excel

Файл `.xlsx` с листами: Panou (сводка, касса по валютам, сотрудники, клиенты, категории), Încasări, Cheltuieli (с колонкой «Plătit din»), Ieșiri, Proiecte, Chirii, Contracte, Salarii и Pontaj, Împrumuturi, Istoric за выбранный месяц. На листах закреплена шапка, включены фильтры, в конце итоговая строка. Даты и суммы — настоящие даты и числа, а не текст. Если библиотека Excel не загрузилась (нет интернета при первом открытии), выгружается CSV.

## 15. Офлайн и защита от потери данных

- Приложение кэширует себя и последние данные на телефоне. Без связи оно открывается и показывает данные.
- Запись без связи сохраняется локально, попадает в списки сразу и ставится в очередь. На экране виден счётчик «N записей ждут отправки». При появлении связи очередь отправляется по порядку; если за это время запись отредактировали, изменения вливаются в неё.
- Если сервер отклонил запись (например, нет описания расхода), она **не удаляется**: остаётся в красной заметке вверху с причиной и кнопками «Повторить» и «Удалить». Удаление требует двух нажатий.
- Кнопка «Сохранить» блокируется на время отправки, двойных записей от двойного нажатия не бывает.
- На сервере каждая запись хранит автора (ставит сервер, не телефон) и попадает в неизменяемую историю.
- Сервер делает полную резервную копию базы каждый день в 03:00, хранит 14 последних.
- Телефон сверяется с сервером при каждом открытии и раз в 3 минуты; если пользователя отключили, приложение закрывается само.

## 16. Как это устроено технически

```
index.html, styles.css, app.js   приложение; без сборки, обычный JS, один файл логики
app-config.js                    адрес сервера (пусто = тот же домен)
vendor/pocketbase.umd.js         клиент PocketBase (SDK 0.28.2)
manifest.json, sw.js, icons/     установка на телефон и офлайн‑кэш (версия кэша в sw.js)
server/pb_migrations/            схема базы и правила доступа (применяются автоматически при старте)
server/pb_hooks/ehl.pb.js        серверная логика
server/install.sh, nginx-site.conf   установка на Ubuntu с nginx
deploy.sh                        выгрузка на сервер и перезапуск
tests/                           тесты и генераторы тестовых данных
tools/make-icons.ps1             генератор иконок приложения
```

**Сервер:** [PocketBase](https://pocketbase.io) 0.40 — один исполняемый файл с базой SQLite, правами доступа, живыми обновлениями и админ‑панелью (`/_/`). Работает как служба `casieria` на `127.0.0.1:8090`, наружу через nginx с сертификатом Let's Encrypt. Данные в `/opt/casieria/pb_data`.

**Коллекции:** `utilizatori` (пользователи), `incasari`, `cheltuieli`, `iesiri`, `chirii`, `contracte`, `imprumuturi`, `proiecte`, `angajati`, `istoric` (история окладов), `pontaj`, `jurnal` (история изменений), `config` (настройки), `login_attempts` (служебная).

**Серверные хуки** (`server/pb_hooks/ehl.pb.js`):
- `POST /api/ehl/login {cod[, parola | parolaNoua]}` — вход по коду; для директора запрашивает или задаёт пароль, выдаёт токен на 7 дней; оператору — на год; считает неудачные попытки по IP.
- `POST /api/ehl/password {veche, noua}` — смена пароля директора, возвращает новый токен.
- При создании записи сервер сам ставит автора (`by`), при редактировании не даёт его изменить.
- Пользователь: случайные email/пароль (не используются), проверка кода, запрет отключить или понизить самого себя.
- Расход без описания отклоняется.

**Живые обновления:** телефоны подписаны на изменения коллекций; запись, внесённая на одном телефоне, появляется у остальных без обновления страницы.

**Права (правила коллекций):**

| Коллекция | Чтение | Создание | Изменение | Удаление |
|---|---|---|---|---|
| журналы (cheltuieli, iesiri и т.д.) | все активные | все активные | свои строки не старше 15 дней; директор любые | директор |
| incasari (поступления от клиентов) | все активные | директор | свои строки не старше 15 дней; директор любые | директор |
| istoric (оклады) | директор | директор | директор | директор |
| pontaj | свои; директор все | все | свои; директор | директор |
| utilizatori | только себя; директор всех | директор | директор | директор |
| jurnal | директор | все | никто | никто |
| config | все | директор | директор | никто |

«Никто» означает: только суперпользователь в админ‑панели.

## 17. Безопасность

- Коды и пароли проверяются только на сервере; на телефоне хранится токен. Пароли хэшированы.
- Защита от перебора: 8 неудачных попыток с IP за 15 минут → отказ на 15 минут. Реальный IP берётся из заголовка nginx.
- Сервер базы недоступен снаружи, только через nginx по HTTPS. Заголовки HSTS, nosniff, X‑Frame‑Options; индексация запрещена.
- Автор записи и история изменений контролируются сервером, клиент их подделать не может.
- Данные никуда не уходят: нет сторонних сервисов, аналитики и облаков; внешние запросы только за шрифтами и библиотекой Excel.
- Админ‑панель `/_/` защищена паролем суперпользователя, он лежит на сервере в `/opt/casieria/ADMIN.txt` (только root).
- Ссылку на приложение не стоит публиковать: коды операторов короткие.

## 18. Установка, обновление, резервные копии

**Нужно:** VPS с Ubuntu, установленные nginx и certbot, поддомен с A‑записью на сервер (без прокси Cloudflare), SSH‑доступ root.

**Первая установка.** С компьютера из папки проекта (Git Bash):
```bash
bash deploy.sh root@SERVER          # копирует файлы в /opt/casieria
```
На сервере:
```bash
bash /opt/casieria/install.sh casa.example.com admin@example.com 'ПарольАдминки'
```
Скрипт скачивает PocketBase, применяет схему, создаёт службу, сайт nginx и сертификат. Ничего другого на сервере не трогает. Затем открыть адрес, ввести код (он станет кодом директора) и задать пароль.

**Обновление приложения.** Поменять версию кэша в `sw.js` (`casieria-ehl-vN`) и выполнить `bash deploy.sh root@SERVER`. Телефоны подхватят новую версию при следующем открытии. Новые миграции применяются автоматически при перезапуске.

**Обновление PocketBase.** Поменять `PB_VERSION` в `server/install.sh` и запустить его снова.

**Резервные копии.** Автоматически каждый день в 03:00 в `pb_data/backups`, 14 последних. Вручную и восстановление: админ‑панель → Settings → Backups. Вся база — папка `/opt/casieria/pb_data`, её можно копировать целиком.

**Логи:** `/opt/casieria/std.log`; состояние службы: `systemctl status casieria`.

## 20. Известные ограничения

- Возврат займа не возвращает деньги в кассу автоматически; приход проводится отдельно.
- Договоры сопоставляются с поступлениями по имени клиента: два договора одного клиента считаются дважды.
- Имена людей, клиентов, категорий — текст; писать нужно одинаково.
- Расход всегда в леях. Покупка напрямую с полки EUR оформляется как выдача себе в EUR плюс расход в леях.
- Все итоги накопительные с первого дня. При росте базы до десятков тысяч записей понадобится «закрытие года» с переносом остатков.

## 21. Типичные ситуации, пошагово

**Клиент заплатил 5 000 EUR наличными.** Încasare: valuta EUR, curs подставился (например 20,22), suma 5000, mod Numerar. Полка EUR +5 000, Încasări +101 100 лей.

**Директор выдал рабочему 1 000 EUR на материалы.** Ieșire: Dat persoanei, EUR, 1000, persoana — рабочий. Полка EUR −1 000; у рабочего аванс +20 220 лей.

**Рабочий купил цемент на 12 000 лей.** Cheltuială: suma 12000, описание «Ciment M400, 40 saci», categorie Materiale, platit de — он, Numerar, Plătit din — Avansul. Аванс рабочего −12 000; Cheltuieli +12 000.

**Рабочий доплатил 800 из своих.** Та же форма, Plătit din — Banii mei. Его баланс уменьшается ещё на 800; у директора видно «din banii proprii 800».

**Внесли 50 000 лей на счёт.** Ieșire: Depus pe cont, MDL, 50000. Полка MDL −50 000, Cont +50 000.

**Заплатили зарплату за октябрь 7 000.** Ieșire: Salarii, MDL, 7000, persoana, luna 2026‑10. Касса −7 000; в Salarii «Plătit» за октябрь +7 000.

**Оплатили аренду квартиры рабочих 350 EUR наличными.** Chirie: EUR, chirie 350, comunale 60, Numerar. Полка EUR −410.

**Дали в долг 8 000 лей.** Împrumut: suma 8000, termen, Neachitat, галочка «вышли из кассы». Касса −8 000; в Împrumuturi «de recuperat 8 000». Вернул — поставить Achitat и провести приход отдельно.

**Новый сотрудник.** Setări → Utilizatori → +: имя, код, галочка «и в сотрудники» с окладом. Сообщить ему код.

**Сотрудник ушёл.** Открыть его в Utilizatori, статус Inactiv. В Salarii сотрудника тоже можно поставить Inactiv, табели и история остаются.
