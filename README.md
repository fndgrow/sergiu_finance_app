# Casieria EHL

Мобильная касса для строительной фирмы (Молдова): поступления, расходы, выдачи из кассы, аренда, займы, договоры, табель и зарплаты, проекты с бюджетами, журнал всех изменений и выгрузка в Excel. Два языка интерфейса: румынский и русский. Ставится на телефон как приложение (PWA), работает офлайн и досылает записи при появлении связи. Данные общие для всех сотрудников фирмы; директор видит сводку и журналы, операторы только вносят.

Логика расчётов повторяет Excel‑файл «Evidență casierie EHL», с которого всё началось: касса по валютам, счёт, остатки у сотрудников, договоры, зарплата по рабочим дням.

## Устройство

```
index.html, styles.css, app.js   приложение (без сборки, обычный JS)
app-config.js                    адрес сервера (пусто = тот же домен)
vendor/pocketbase.umd.js         клиент PocketBase
manifest.webmanifest, sw.js, icons/   установка на телефон, офлайн‑кэш
server/pb_migrations/            схема базы и правила доступа
server/pb_hooks/                 серверная логика: вход по коду, защита от перебора, автор записи
server/install.sh                установка на Ubuntu с nginx (один раз)
server/nginx-site.conf           шаблон сайта nginx
deploy.sh                        выгрузка на сервер и перезапуск
tools/make-icons.ps1             генератор иконок
```

Бэкенд: [PocketBase](https://pocketbase.io) — один исполняемый файл с базой SQLite, правами доступа, живыми обновлениями и админ‑панелью. Данные лежат в `/opt/casieria/pb_data` на нашем сервере и никуда не уходят.

## Как устроен доступ

- Сотрудник вводит только числовой код (4–8 цифр). Сервер (`server/pb_hooks/ehl.pb.js`, маршрут `/api/ehl/login`) проверяет код и выдаёт токен на год. Восемь неверных попыток с одного IP за 15 минут блокируют вход на 15 минут.
- При самом первом запуске на пустой базе введённый код становится кодом директора.
- Правила на коллекциях (`server/pb_migrations/…init.js`): оператор читает все журналы кроме окладов, создаёт записи, редактирует только свои, не удаляет. Директор видит всё, удаляет, управляет пользователями и настройками. Журнал изменений (`jurnal`) только дописывается; изменить или удалить его нельзя даже директору (только суперпользователь в админ‑панели).
- Автор записи (`by`) ставится сервером, клиент его не контролирует.
- Отключили сотрудника (статус Inactiv), и его телефон теряет доступ при следующем запросе.

## Установка на сервер (Ubuntu + nginx)

Нужно: VPS с Ubuntu, nginx и certbot уже стоят, поддомен (например `casa.fndgrow.md`) указывает A‑записью на сервер, SSH‑доступ root.

1. С компьютера, из этой папки, в Git Bash:
   ```bash
   bash deploy.sh root@SERVER        # или алиас из ~/.ssh/config
   ```
   Копирует приложение в `/opt/casieria/pb_public`, хуки и миграции в `/opt/casieria`.
2. На сервере, один раз:
   ```bash
   bash /opt/casieria/install.sh casa.fndgrow.md admin@example.com 'ПарольАдминки'
   ```
   Скачивает PocketBase, применяет схему, создаёт службу `casieria` (слушает только 127.0.0.1:8090), добавляет сайт nginx для домена и получает сертификат Let's Encrypt. Ничего другого на сервере не трогает. Если домен ещё не указывает на сервер, запускайте с `SKIP_NGINX=1`, а потом повторите без него.
3. Откройте `https://casa.fndgrow.md`, введите код, он станет кодом директора. В Setări → Utilizatori поменяйте имя, заведите сотрудников с их кодами.

Админ‑панель PocketBase: `https://домен/_/` (логин и пароль из шага 2). Там видны все таблицы, есть резервные копии и просмотр логов.

## Обновление

```bash
bash deploy.sh root@SERVER
```
Перед этим поменяйте версию кэша в `sw.js` (`casieria-ehl-v1` → `v2`), иначе телефоны будут показывать старую версию до следующего дня.

## Резервная копия

Вся база — папка `/opt/casieria/pb_data`. Копировать её целиком (`rsync` или встроенные бэкапы в админ‑панели: Settings → Backups, можно по расписанию).

## Установка на телефон

- Android, Chrome: открыть ссылку, в приложении появится кнопка «Instalează pe telefon», или меню ⋮ → «Добавить на главный экран».
- iPhone, Safari: «Поделиться» → «На экран Домой». Ставить именно из Safari.

## Известные ограничения

- Возврат займа не возвращает деньги в кассу (так и в исходной таблице): возврат нужно провести как поступление.
- Договоры сопоставляются с поступлениями по имени клиента, два договора одного клиента считаются дважды.
- Имена людей и клиентов сравниваются как текст, писать нужно одинаково.
- Касса, счёт и остатки считаются с первого дня накопительно. При росте базы до десятков тысяч записей понадобится «закрытие года» с переносом остатков.

## Разработка и проверка

Сборки нет: файлы правятся напрямую. Дымовой тест (jsdom с имитацией PocketBase) проверяет вход, формы, расчёты, офлайн‑очередь и роли:

```bash
npm install jsdom
node tests/smoke.js .
```
